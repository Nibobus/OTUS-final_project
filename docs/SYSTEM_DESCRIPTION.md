# Архитектура и бизнес-логика ИС

## Основные бизнес-процессы
1. **Приемка:** Товар поступает на зону `Receiving`, регистрируется в `movements` (тип Inbound), затем распределяется по зонам `Storage` через таблицу `inventory`.
2. **Отгрузка:** При создании `orders` система должна проверять `available_qty` (quantity - reserved_qty). Если запаса хватает, объем резервируется (увеличивается `reserved_qty`).
3. **Инвентаризация:** Создается запись в `inventory_audits`. Система снимает снапшот `system_qty`. Кладовщик вводит `actual_qty`. Поле `discrepancy` автоматически считает разницу.
4. **Авто-закупка:** Процедура `sp_auto_replenishment` сравнивает текущий доступный остаток с `reorder_point`. Если порог достигнут, создается заказ поставщику с учетом `lead_time_days`.

## Аналитическая ценность
Система не просто хранит остатки, но и предоставляет данные для:
* **Оптимизации складской логистики:** Анализ оборачиваемости по зонам позволяет переместить товары класса "А" в зоны "Picking" (быстрой сборки), сократив время прохождения заказа.
* **Финансового контроля:** Отчет по стоимости запасов в разрезе ABC-классов помогает выявить неликвиды (класс С) и заморозку капитала.
